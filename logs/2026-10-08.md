  BR-C6.
- CLI: `sheet-diff old new [--json] [--key ...]` (+ `merge` placeholder wired

## Compare fixtures landed → golden suite green

Owner delivered the real compare fixture
(`Sales_Register_Sep2026_v1.xlsx` → `..._FINAL.xlsx`, `expected.json`,
`reference_report_prototype.xlsx`), copied into `docs/fixtures/compare/`.
Rewrote `test/golden/compare.golden.test.ts` against the real schema; it now
passes (8 assertions): 8 real changes, 4 high (CHK-01/02/03/04), CHK-05 +
CHK-09, `mustNotFire` (CHK-06/07/10) silent, Summary has no real change
(ranges cancel), positional baseline exactly 89 on Sales Register.

Running against ground truth surfaced and fixed three real bugs:
1. **Dates read as plain numbers** — `XLSX.SSF` is undefined on SheetJS 0.18.5's
   ESM named import, so date-format detection silently failed and CHK-04 never
   fired. Replaced with a self-contained `isDateFormat` and always read number
   formats (`cellNF: true`).
2. **CHK-05 picked the wrong ID column** ("Invoice No" matched `/no/`), so the
   Desai-Traders two-GSTIN finding never fired. Now excludes the key column and
   prefers GSTIN/PAN headers.
3. **Positional baseline counted the title rows** — scoped it to the union of
   the data ranges (TDD §7.8); Sales Register is now exactly 89, not 90.
Plus a display fix: percentage columns ("GST %") are no longer ₹-formatted.
Full suite: 57 tests green.

## Increment 2 — assisted-merge engine (TDD §9)

Owner delivered the merge fixture (`Sales_Register_Sep2026_ORIGINAL.xlsx` +
`..._RAVI.xlsx` + `..._PRIYA.xlsx` + `expected.json`), copied into
`docs/fixtures/merge/`. Built the merge engine on top of the compare core:

- `merge/diff.ts` — structured per-sheet diff (edits / added+anchor+cells /
  removed) reusing `compareCore`, so recalculated-vs-real classification and
  BR-C3 range shifts are identical to compare. Carries each inserted row's
  source row for formula re-anchoring.
- `merge/plan.ts` — `planMerge` classifies every key per the §9.1 table into
  auto-proposals and CELL / RELATED_EDITS / DELETE_EDIT / ADD_ADD / STRUCTURE
  conflicts. Matches the fixture exactly: **5 proposals, 3 conflicts**
  (CELL INV-1003, RELATED_EDITS INV-1008, DELETE_EDIT INV-1019).
- `merge/resolve.ts` — `resolveMerge` → `MergeChangeSet` (cell edits, row
  inserts/deletes, extend-ranges); refuses while a conflict is open
  (`MERGE_UNRESOLVED`); RELATED_EDITS "both" needs the acknowledgement (BR-M4).
- `merge/impact.ts` — virtual merged model (base + edits + inserts/deletes with
  per-row formula re-anchoring); `previewImpact` evaluates every total formula
  before/after; `computeExtendRanges` runs the CHK-02 logic on the merged model.
- `merge/log.ts` — the 8-row Merge Log (5 auto + 3 resolved) with who/what/
  old/new (BR-M8).

Impact matches `summaryAfterExcelRecalculates` to the paisa: invoices 30,
Total taxable ₹14,84,624, @5% ₹2,92,000, @18% ₹11,92,624, **Total GST payable
₹2,29,272.32**, Total invoice value ₹17,13,896.32. With extend off it
under-reports (₹2,19,066.32), which is the CHK-02 warning case.

### Bug fixed against ground truth
`previewImpact` keyed extend-ranges by cell, so for a two-range `SUMIF` the
second range (sum range) overwrote the first (criteria range) — the criteria
range stayed short and dropped the appended INV-1031 (18%, ₹56,700) from the
`@18%` bucket. Now all extend entries per cell are applied.

CLI `merge <base> <copy1> <copy2> [--json]` added. 64 tests green (incl. the
new 7-assertion merge golden). The patch writer (§10) is the next increment.

## Increment 3 — OOXML patch writer (TDD §10)

Built `src/patch/` to write the merged `.xlsx` from a change set, validated by
LibreOffice recalculation.

- `zip.ts` / `parts.ts` — fflate unzip/zip (untouched parts kept byte-for-byte);
  resolve workbook sheets → worksheet paths, date1904, next rId/sheetId.
- `worksheet.ts` — parse `<sheetData>` into rows/cells preserving raw content;
  renumber rows + cells; re-emit (fidelity-preserving, §10.1).
- `cells.ts` — cell writes (number / inline string / boolean / formula), keeping
  the style `s`; inline strings avoid touching sharedStrings.
- `formulas.ts` — rewrite a cell's `<f>` via translation; drop the stale `<v>`.
- `apply.ts` — pure `computeRowMap` (base→merged, deletes = −1, below shift) +
  `applyToWorksheet` (deletes/inserts/edits, same-sheet formula re-anchor,
  inserted-row formulas re-anchored by source-row delta) +
  `rewriteReferencingSheet` (Summary → Sales Register translate + extend).
- `merge-log-sheet.ts` — new "SheetLens Merge Log" worksheet part + workbook
  `<sheet>` + rels + `[Content_Types]` + app.xml counts (§10.6).
- `calc.ts` — `fullCalcOnLoad` + drop `calcChain` (§10.7).
- `blockers.ts` — §10.5 unsafe row-op detection (pivots/charts/drawings/
  comments/arrays); none in this fixture.
- `csv-writer.ts` — CSV-original rewrite path; `index.ts` — `applyMergePatch`
  orchestration + optional re-encrypt; `selfcheck.ts` — re-read & verify
  (`PATCH_SELFCHECK_FAILED` on mismatch).

**Golden (LibreOffice headless):** the patched merge fixture opens cleanly and
recalculates to invoices **30**, Total taxable ₹14,84,624, @5% ₹2,92,000,
@18% ₹11,92,624, **Total GST payable ₹2,29,272.32**, Total invoice
₹17,13,896.32 — exactly `summaryAfterExcelRecalculates`. Merge Log has 8 rows,
0 blocked, self-check passes. CLI: `merge … --resolve K=CHOICE --extend-totals
--out merged.xlsx`. 68 tests green.
